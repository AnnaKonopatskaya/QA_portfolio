# API-тестирование: FakeStore API (Postman)

**Тип работы:** тестовое задание / практика по API-тестированию
**Объект тестирования:** [FakeStore API](https://fakestoreapi.com/) - публичное REST API интернет-магазина
**Инструмент:** Postman, коллекция v2.1

## Задача

Собрать Postman-коллекцию для проверки основных CRUD-операций по двум ключевым сущностям API: `Products` и `Carts`.

## Покрытие

### Products
| Метод | Endpoint | Проверка |
|---|---|---|
| GET | `/` | Получение списка всех товаров |
| GET | `/products/1` | Получение одного товара по ID |
| POST | `/products` | Создание нового товара |
| PUT | `/products/1` | Обновление товара |
| DELETE | `/products/2` | Удаление товара |

### Carts
| Метод | Endpoint | Проверка |
|---|---|---|
| GET | `/carts` | Получение списка всех корзин |
| GET | `/carts/1` | Получение одной корзины по ID |
| POST | `/carts` | Создание новой корзины |
| PUT | `/carts/2` | Обновление корзины |
| DELETE | `/carts/3` | Удаление корзины |

Всего покрыты все базовые CRUD-операции (Create / Read / Update / Delete) для обеих сущностей - 10 запросов.

Каждый запрос назван по схеме `<ожидаемый код ответа>: <действие>` (например, `200: Get all products`) - это сразу показывает, какой результат считается успешным для проверки.

Переменная `{{baseUrl}}` вынесена в коллекцию, что позволяет быстро переключаться между окружениями (например, между реальным API и локальным mock-сервером).

## Как использовать

1. Импортировать [`FakeStore_API.postman_collection.json`](./FakeStore_API.postman_collection.json) в Postman.
2. Задать переменную `baseUrl` (например, `https://fakestoreapi.com`).
3. Запустить коллекцию целиком через Collection Runner или выполнять запросы по отдельности.
